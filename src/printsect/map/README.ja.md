# map — C のプロジェクトで、どのモジュールがどのモジュールを使っているか

[English](README.md) | 日本語

`psect-map` はプロジェクトの C のソースを読み、知らないコードについて最初に知りたいことに答えます：どんな
部分からできていて、どの部分がどれを使い、入口はどこか。AI エージェントが作業を始める前に読める短さです。
単独で動きます。printsect の中では `psect map` で、ビルドのアーカイブ単位でまとめ、プローブの場所にも印を付けます。

ファイルを読むだけで、何も実行しません：コンパイラも make も索引のプログラムも使いません。なので、設定の前
から使え、承認も要りません。

```
948 source file(s), 22 module(s) by directory, counts are (symbol, using file) pairs
crypto/evp/  core  files 61  in 1519 (16)  out 358 (12)
crypto/bn/  core  files 33  in 1054 (14)  out 19 (4)
uses (user -> used):
  crypto/ec/ -> crypto/bn/  313
left out: same name in several files 80 symbol(s) (391 use(s)); static elsewhere 4833
```

`in 1054 (14)` は、ほかの 14 モジュールから 1054 の利用があるという意味です。`start` はほかを使い、誰からも使われ
ないもの、`base` は使われるだけのもの、`core` は 3 つ以上から使われ、自分もほかを使うものです。

`cycles` は、直接またはほかを経由して互いに使い合っているモジュールを、一周する最短の経路とその上のシンボル付きで
示します。ないときは `cycles: none` と出します。

## コマンド

| コマンド | 内容 |
|---|---|
| `psect-map` | 全体図：使われている数の多いモジュールから順に、誰が誰を使っているか |
| `psect-map focus MODULE` | 1 つのモジュール、アーカイブ、または任意のフォルダ：誰がどのシンボルで使っているか、何を使っているか、中で何が起きているか、各ファイルの位置づけ（`entry` = 外から使われる） |
| `psect-map who NAME` | 1 つの関数、変数、ファイルを誰が使っているか：定義の場所、使っているファイルと行、定義が複数あるときはその理由 |

どれも `--top N`（一覧ごとの行数。既定は 30。切った分は件数を出します）、`--by-dir`（アーカイブが分かっていても
フォルダでまとめる）、`--json`、`--root DIR` を受け付けます。各シンボルには、定義しているファイルと行が付きます。

## 数えるもの

- 利用は、行数ではなく（シンボル, 使っているファイル）の組で数えます。1 つのファイルから 10 回呼んでも 1 です。
- 数えるのは、ソースファイルで定義された関数と変数を、ソースファイルから使っているものだけです。ヘッダはほとんど
  宣言で、数えても「みんな公開ヘッダを読み込んでいる」と分かるだけです。
- 推測はしません。複数のファイルに定義があり、使う側がどれを指すか決められない名前は外します。ほかのファイルの
  `static` にしか定義がない名前も、C の規則で届かないので外します。外した数は必ず答えに含まれ、`map.exclude` で
  外したパスの数も出します。
- `#if` の中の定義は、ビルドで外れるかもしれなくても数えます。その数も答えに出します。

モジュールは最上位のフォルダで、重いものは分割し、大きいフォルダはその部分ごとに見せます。一部を切り出された
フォルダは、残りを表します。`psect map` では、`psect deps` がビルドを読んだあとは、モジュールはアーカイブになり、
ビルドが使わないファイルは外します。これで、機種ごとに定義された同じ名前の多くも解決します。

## 見えないもの

コンパイラを使わず、コードの形を読みます：

- 関数ポインタ経由の呼び出しには、突き合わせる名前がありません。
- `#if` は評価しません（`#if 0` を除く）。どちらの枝も数えるので、一緒にビルドされないコードどうしが循環に見えることがあります。
- マクロが名前を作る関数や変数は見つかりません（"named by a macro" として数えます）。
- ヘッダのマクロの中で行う呼び出しは、関数ではなくマクロの名前として見えます。
- ほかのファイルのグローバルと同じ名前のローカル変数は、その利用として数えます。

OpenSSL 1.1.1q で、同じツリーの GNU Global の索引から作ったマップと比べました（テスト用のフォルダは除く）。そのマップの
利用の 97% を見つけ、見つけたものの 97% がそのマップにありました。そのマップだけにあった 284 件のうち 197 件は、`a` という
1 つの名前を、名前だけで突き合わせたものでした。こちらだけが見つけた 358 件をソースで確かめると、350 件は実際に使われていて
（呼び出し 230 件、名前として 120 件）、8 件は構造体のメンバーか前処理の行だけでした。

## 設定（`printsect.yaml`、すべて省略可）

```yaml
map:
  exclude: ["third_party/*", "tests/*"]    # プロジェクトのルートからのパスのパターン
  extensions: [.c, .cc, .cpp, .cxx]
  encodings: [utf-8, cp932]
```

`.` で始まるフォルダは飛ばし、リンクはたどりません。4 MB を超えるファイル（たいてい生成された表）と 64 KB を超える宣言は数えて外します。

速度（OS がファイルを一度読んだあと）：OpenSSL 1.1.1q のソース 948 ファイルは、初回 1.6 秒、以後 0.3 秒でした。約 100 万行
（8,000 ファイル）は、初回 11 秒、以後 3 秒でした。読み直すのは変わったファイルだけです。書かれてからまだ読まれていないファイルは、
Windows ではウイルス対策の検査が 1 つずつ入るため、長くかかります：OpenSSL はコピーした直後で 7 秒でした。

## 別の索引を使う

索引は役割 `indexer` のプラグインです。エントリポイントのグループ `printsect.indexer` で、別のパッケージとして足せます。
`__init__(settings)` と `index(project, log) -> Index` が必要です。`map: {type: <名前>}` で選びます。クラス属性
`SETTINGS`（キー -> 型、`index.py` と同じ形）があれば、printsect がそのキーを確かめます。

## 書くファイル

| ファイル | 用途 |
|---|---|
| `.printsect/map.json` | 各ファイルが定義し、使っているもの。変わったファイルだけを読み直すため |

## 中身

| ファイル | 内容 |
|---|---|
| `cli.py` | コマンド。`configure()` で `psect` が組み込み、アーカイブとプローブの印を足す |
| `scanner.py` | 1 つのファイルの定義と、使っている名前 |
| `index.py` | 標準の索引：プロジェクトをたどること、保存した索引 |
| `model.py` | 索引からモジュール、役割、それぞれの答えへ |
| `cycles.py` | モジュールの間の循環を見つける |
