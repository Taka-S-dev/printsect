# printsect：プロジェクトの設定のしかた

目標は、`doctor` の結果がすべて ok になることです。設定はあなたが自分のファイル編集の機能で書き、
printsect はそれをその場で確かめます（`check`、`doctor`）。プロジェクトの情報を、この PC の外に
出す必要はありません。全設定項目と例は `guide` のトピック `settings` にあります。

ファイルは 2 つで、どちらもプロジェクトのルートに置きます。

- `printsect.yaml` — プロジェクトの全員で共有する設定：deps、build、run、deploy、reproduce、
  stop、devices。
- `printsect.local.yaml` — この PC だけの設定で、コミットしません：コンソール（ポート、プログラム）。

printsect は自分の状態を `.printsect/` に置きます（依存グラフの `deps.json` と `DEPS.md`、
プローブの一覧の `probes.json` と `PROBES.md`、実行ごとのフォルダ）。git からは自動で除外されます。
触らないでください。

ここで使う道具の名前は MCP の道具の名前です。コマンドラインでは、それぞれ `psect` のコマンドに
対応します：`deps_find` は `psect deps find`、`deps_which` は `psect deps which`、`build_plan` は
`psect build --plan`、`probe_add` は `psect probe add`、などです。

## 手順

1. **`init`** で 2 つのファイルを作ります。全セクションが、埋める順番にコメントで入っています。
   既にあるファイルを上書きすることはありません。
2. **deps — ビルドの読み方。** 普段どうビルドしているかを調べます：README、Makefile、ビルド用の
   スクリプト。プロジェクトのルートで `make` とだけ打っているなら、既定の `deps.command`
   （`make -n -B -w`、`.` で実行）のままで正しいです。そうでなければ、普段の make の呼び方に
   `-n -B -w` を足したもの（`-f`、`-C`、ターゲット、変数はそのまま）を `deps.command` に、
   実行する場所を `deps.cwd` に書きます。`doctor` が出力、アーカイブ、ソースの数を数えます。
   ソースが 0 個なら、フォルダかターゲットが違います。念のため、ビルドされると分かっているソースを
   `deps_find` で探し、それが入る出力が表示されることを確かめます。ビルドを読むと make が動き、
   make は `-n` でも Makefile の `$(shell ...)` を実行するので、あなたのためには、相手が
   `psect approve` を実行するまで待ちます。deps を設定したら、相手に頼んでください。
3. **run.banner — 新しいビルドが名乗る場所。** 新しいビルドが起動時に一度だけ必ず実行するコードを
   探します：モジュールの初期化関数や入口の関数（ローダーや起動処理が呼ぶもの）です。`deps_which` で、
   そのファイルが転送される出力に入っていることを確かめます。その関数の中で、文の終わりの行を、
   失敗しうる処理より前の早い位置から選びます。`doctor` がその行を確かめます。
   - **そういう関数が見当たらない**（入口がリンカスクリプトやローダーの表、あるいは相手の頭の中にしかない）
     ときは、読み込み時にどの関数が動くかを相手に聞きます。答えがあるまで `run.banner` は空けておきます。
   - **複数の出力をまとめて転送する**ときも、起動の目印は 1 回の実行に 1 つです。転送するすべての出力が
     起動時に実行するコード（共通のコード）に置きます。共通のコードがなければ、相手が最後に読み込む
     出力に置き、新しいと確かめられるのはその 1 つだけだと伝えます。
4. **build — 出力の作り方。** 普段使っているコマンドと、先にクリーンしているかを調べます。そのうえで：
   - 出力を作るだけで必要なものも作り直される（make ならたいていそう）なら、出力のルール 1 つで
     足ります：`for: outs`、`run: make {path}`。アーカイブを別のコマンドで作っているときだけ、
     `for: archives` のルールを足します。
   - `{path}` はビルドが付けた名前のままの出力（`build/out/netdrv.out`）、`{name}` はファイル名だけで、
     make がそれを知っているのはそのフォルダで実行したときだけです。迷ったら、まず `make -n` で
     そのコマンドを手で試します。ターゲットが存在しなければなりません。
   - `for` のない手順は、その位置で一度だけ実行されます。クリーンするならそこに書きます。
   - `artifacts: auto` はそのままにします。
   - プローブを入れる前に、`build_plan` に `all: true` を付けて計画を見ます（すべてのソースに
     プローブがあると仮定した計画）。最初のビルドの前に、そのコマンドを相手に見せて了承を得ます。
     実際に実行されるからです。
   - あなたが設定に書いたコマンド（ビルド、転送、既定以外の `deps.command`、コマンド型の
     コンソール）は、相手が自分で `psect approve` を実行して承認するまで、あなたのためには
     実行されません。あなたは承認できません。承認されるまで、`build_plan`、`run`、deps と
     コンソールの道具は、そのコマンドを示して断ります。`doctor` もそれを示します。
5. **deploy — ビルドを対象機器に載せる方法。** 聞きます。相手が自分の道具で手で行うなら、
   `type: manual` と、何を読み込むかを書いた `message`。この PC のコマンドで行うなら、
   `type: command` とその `commands`。FTP サーバーが動く対象機器なら `type: ftp` と `host`、
   `user`、`path`、読み込みのコマンドを `after` に。パスワードは `password_env` が指す変数
   （`PSECT_FTP_PASSWORD`）に設定するよう人に頼み、設定ファイルには決して書きません。
   この PC で動かすプログラムなら `type: none`。
   deploy を設定するまで、`doctor` は warn を出します。
6. **console — 対象機器の出力の読み方。** どのプログラムでコンソールを見ているか、どう接続するか
   （その TCP ポート、そのコマンドライン、そのログファイル、または他に使っていなければシリアルポート
   そのもの）を聞きます。`printsect.local.yaml` に書きます。`doctor` が接続し、最後の行番号を表示します。
7. **run.ready、reproduce、stop。** 対象機器がコマンドを受け付けられるようになったとき何を出すか
   （プロンプト）、問題をどう起こすか、どの出力で終わったと見なすか（例外の文字列、出力がない時間）を聞きます。
8. **devices — 対象機器ごとに違いがあるときだけ。** 何が違うか（出力の置き場所、読み込み方、ポート）を
   聞きます。機器ごとに、違う設定だけを書いて名前を付けます。`use` で選ぶのは、相手がどれかを言ったときだけです。
9. **最後まで通して確かめる。** `doctor` がすべて ok になったら、起動の目印の関数（必ず実行される）に
   プローブを 1 つ入れて `run` し、ヒットすることを確かめます。そのあと取り除きます。

## 決まり

- **推測せず、聞く。** ポート、プログラム、転送の方法、どの機器か、読み込み時にどの関数が動くか
  （見て分からないとき）、そして対象機器をリセット・消去・書き換え・再起動するコマンド。推測した
  ポートやローダーのコマンドは、質問では起きない損害を起こしえます。
- `doctor` がすべて ok でも、それだけでは設定は終わりではありません。上の手順で「聞く」とある項目は、
  すべて相手に答えてもらうか、意図して空けたことを伝えておきます。
- printsect に合わせるために、プロジェクトのビルド用のファイル（Makefile、スクリプト）を変えないでください。
  ビルドは今あるとおりに記述します。
- 共有する設定は `printsect.yaml`、この PC だけの設定は `printsect.local.yaml` に書きます。
- 変更のたびに：`check` は書き間違えた項目を、近い正しい名前と一緒に示します。`doctor` は次にやることを
  示します。示されたことを、一つずつ直します。
- `probe_add` は、指定した行の下にプローブを入れます。グループは任意の名前で、まとめて一覧したり
  取り除いたりするのに使います。
